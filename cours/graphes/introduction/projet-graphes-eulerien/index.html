Pourquoi utiliser une telle structure ?

corrigé

La complexité "utile" en code est souvent la complexité en moyenne puisque nous allons utiliser nos algorithmes pour de nombreux graphes différents. Donc si la complexité en moyenne de l'utilisation d'une structure est bonne (voir très bonne ici puisque toutes les complexités sont en $\mathcal{O}(1)$ en moyenne) et que sa manipulation est aisée on préférera l'utiliser même si sa complexité max peut être mauvaise ($\mathcal{O}(n)$ (avec $n$ le nombre de sommets) dans le pire des cas).

Attention cependant, cette structure est mutable : on peut modifier les sommets et les voisins. donc pour copier un graphe il faudra non seulement faire un nouveau dictionnaire mais aussi des nouveaux ensembles de voisins !

Pour tout copier en une seule fois on utilisera le module copy de python :

import copy

G2 = copy.deepcopy(G)

On aurait pu faire la copie en une ligne avec les list comprehension de python : G2 = {k: set(v) for k, v in G.items()}

Algorithmes

On veut que notre algorithme principal soit de ce type :

import copy

def cycle_eulérien(G):
    G = copy.deepcopy(G)

    cycles = []
    while G:
        c = cycle(G)
        cycles.append(c)
        supprime_arêtes_du_cycle(c, G)
        supprime_sommets_degré_zéro(G)

    concatène_cycles(cycles)
    return cycles[0]

Où cycle(G) est un algorithme permettant de concaténer une liste de cycles en un liste plus petite de cycles disjoints (un seul élément à la fin si ce sont les cycles d'un graphe eulérien connexe).

On va coder les différents algorithmes !

Codez l'algorithme cycle(G) qui rend un cycle élémentaire $[x_0, \dots, x_p]$ (avec $x_0 = x_p$) d'un graphe où $\delta(x) > 1$ pour tout sommet $x$.

Trouver un cycle peut se faire en utilisant l'algorithme du cours cycle_non_orienté(G,x) (même s'il n'est pas optimal, pour de petits graphes le temps de calcul ne sera pas rédhibitoire). Il faut juste trouver un sommet de départ, mais comme tous les sommets on un degré strictement positif, on peut prendre n'importe lequel.

Une fois cet algorithme codé le reste de la boucle est facile à implémenter :

Codez les algorithmes :

  • supprime_arêtes_du_cycle(c, G) qui supprimes les arêtes du cycle c dans G,
  • supprime_sommets_degré_zéro(G) qui supprimes les sommets de G de degré 0

Le dernier algorithme à créer est celui concaténant deux cycles. On va suivre le cours pour écrire :

def concatène_cycles(cycles):
    while len(cycles) > 1:
        c = cycles.pop()
        for i in range(len(cycles)):
            intersection = set(c).intersection(set(cycles[i]))
            if intersection:
                x = intersection.pop()
                cycles[i] = concatène(cycles[i], c, x)
                break

Avec l'algorithme concatène(c1, c2, x) qui rend la concaténations des cycles c_1 et c_2 via x qui est un somment commun.

Codez les algorithmes concatène_cycles(cycles) et concatène(c1, c2, x).
