Algorithmes récursifs et itératifs

Cours/Algorithmie/Partie I : Écrire des algorithmes/Pseudo-code/Algorithmes récursifs et itératifs

Il y a deux grandes familles d'algorithmes :

  • les algorithmes itératifs, c'est à dire utilisant des boucles
  • les algorithmes récursifs, c'est à dire écrit sous la forme d'une fonction qui s'appelle elle même.

Tout algorithme pourra toujours s'écrire sous une forme itérative ou récursive (on va le montrer mais bien plus tard) mais certains problèmes se résolvent mieux sous une forme que l'autre.

Avant de définir formellement les deux approches commençons par deux remarques importantes :

À retenir

Adaptation d'un algorithme aux données :

  1. pour que la sortie d'un algorithme dépende de ses entrées, il est nécessaire qu'il possède des instructions conditionnelles (sinon il fera toujours la même chose),
  2. pour qu'un algorithme puisse traiter des entrées de taille quelconque, il est nécessaire de répéter certaines de ses instructions (sinon il ne ne pourra traiter entièrement des données plus grandes que son nombre d'instructions).

La différence entre les approches itératives et récursive est lié au traitement des deux points précédents.

Pour expliciter la différence entre les deux approches nous allons utiliser notre exemple fil rouge du calcul du $\operatorname{pgcd}$.

Algorithmes Itératif

Définition

Un algorithme itératif va gérer les 2 points d'adaptation aux données en modifiant des variables locales et en utilisant des boucles pour chaque et tant que. Il va avoir tendance à aller du cas particulier vers le cas général en stockant les éléments intermédiaires dans des variables.

Pour le calcul du $\operatorname{pgcd}$, l'algorithme itératif va tester tous les cas possibles :

algorithme pgcd(a: int, b: int) → int:  # a, b ≥ 0
    ref pgcd int

    pour chaque k de [1 .. min(a, b)]:
        si (a mod k == 0) ET (b mod k == 0):
            pgcd ← k
    
    rendre pgcd

code python

 
def pgcd(a, b):
    pgcd = 0
    for k in range(1, min(a, b) + 1):
        if (a % k == 0) and (b % k == 0):
            pgcd = k
    
    return pgcd

Lorsque l'on construit un algorithme itératif, il faut faire attention au fait que les boucles finissent bien. C'est bien sur toujours le cas avec les boucles de type pour chaque mais pour des boucles de type tant que ce n'est pas toujours évident.

Algorithmes Récursif

Définition

Un algorithme récursif va gérer les 2 points d'adaptations aux données en se rappelant lui-même (une récursion) avec de nouveaux paramètres d'entrées un nombre fini de fois (nécessite une condition d'arrêt pour stopper la récursion). Il va avoir tendance à aller du cas général vers le cas particulier en stockant les éléments intermédiaires dans ses paramètres d'entrées.

Pour le calcul du $\operatorname{pgcd}$ on va utiliser l'algorithme binaire de Stein :

algorithme pgcd(a: int, b: int) → int:  # a, b ≥ 0
    si min(a, b) == 0:
        rendre max(a, b)
    sinon si a == b:
        rendre a
    sinon si (a mod 2 == 0) ET (b mod 2 == 0):
        rendre 2 * pgcd(a // 2, b // 2)
    sinon si (a mod 2 == 0):
        rendre pgcd(a // 2, b)
    sinon si (b mod 2 == 0):
        rendre pgcd(a, b  // 2)
    sinon si a > b:
        rendre pgcd(a - b, b)
    sinon:
        rendre pgcd(a, b - a)

code python

 
def pgcd(a, b):
    if min(a, b) == 0:                     
        return max(a, b)
    elif a == b:
        return a    
    elif (a % 2 == 0) and (b % 2 == 0):
        return 2 * pgcd(a // 2, b // 2)
    elif (a % 2 == 0):
        return pgcd(a // 2, b)
    elif (b % 2 == 0):
        return pgcd(a, b  // 2)
    elif a > b:
        return pgcd(a - b, b)
    else:
        return pgcd(a, b - a)

À chaque récursion soit $a$ soit $b$ (ou les deux) diminue strictement : à chaque itération on se rapproche donc des deux cas sans récursion qui mettent fin à l'algorithme.

Notre algorithme effectue 5 récursions avant de terminer pour calculer le pgcd entre 8 et 6 :

pgcd(8, 6) = 2 * pgcd(4, 3)
                 pgcd(4, 3) = pgcd(2, 3)
                              pgcd(2, 3) = pgcd(1, 3)
                                           pgcd(1, 3) = pgcd(1, 2)
                                                        pgcd(1, 2) = pgcd(1, 1)
                                                                     pgcd(1, 1) = 1

Pour comprendre comment cela fonctionne il faut se rappeler qu'un algorithme passe à la ligne suivante que si l'instruction est terminée : lors d'une récursion l'algorithme attend que la récursion se termine pour continuer. Ainsi lors du 5 appel de récursion, il y a 5 algorithmes qui attentent :

  • pgcd(1, 2) attend en ligne 11 que la fonction pgcd(1, 1) se termine pour continuer
  • pgcd(1, 3) attend en ligne 15 que la fonction pgcd(1, 2) se termine pour continuer
  • pgcd(2, 3) attend en ligne 9 que la fonction pgcd(1, 3) se termine pour continuer
  • pgcd(4, 3) attend en ligne 9 que la fonction pgcd(2, 3) se termine pour continuer
  • pgcd(8, 6) attend en ligne 7 que la fonction pgcd(4, 3) se termine pour continuer

Lorsque la dernière récursion s'arrête : pgcd(1, 1) rend 1 sans récursion, qui permet à l'algorithme pgcd(1, 2) de s'arrêter qui permet à l'algorithme pgcd(1, 3) de s'arrêter qui permet à l'algorithme pgcd(2, 3) de s'arrêter qui permet à l'algorithme pgcd(4, 3) de s'arrêter qui permet à l'algorithme pgcd(8, 6) de s'arrêter.

Notez que nous n'avons pas prouvé que le programme trouve bien le plus grand diviseur commun de deux entiers, juste qu'il se termine quelque soit ses entrées et donc que c'est un algorithme. Démontrons le :

Proposition

L'algorithme binaire de Stein calcule bien le $\operatorname{pgcd}$ de deux entiers positifs donné en paramètre.

preuve

L'algorithme effectue plusieurs cas que nous allons examiner :

  • si min(a, b) == 0 : le $\operatorname{pgcd}$ est clairement $\max(a, b)$,
  • si min(a, b) > 0 et a == b : le $\operatorname{pgcd}$ est clairement $a$,
  • si a et b sont pairs 2 est un diviseur commun
  • si seul a ou b est pair, 2 n'est pas un diviseur commun
  • sinon, on retrouve l'algorithme d'Euclide que l'on a démontré correct.

Récursion terminale

Récursion terminale

La récursion terminale est un algorithme écrit sous une forme récursive pouvant facilement se mettre sous forme itérative :

Définition

Soit l'algorithme f suivant où c: A → Booléen, g: A → B et h: A → A sont trois fonctions parfaitement définies :


algorithme f(n: A) → B:
    si c(n) == Vrai:
        rendre g(n)
    sinon:
        rendre f(h(n))

L'algorithme f est sous la forme d'une récursion terminale, c'est à dire que :

  1. soit il s'arrête si une condition d'arrêt est vérifiée
  2. soit il rend une récursion de lui même

Pour que la définition de f ait du sens il faut bien sur que chaque récursion se rapproche de la condition d'arrêt. C'est ce qu'il faut démontrer pour chaque algorithme sous la forme d'une récursion terminale.

La récursion terminale est sympathique car équivalente à la forme itérative suivante :

algorithme f(n: A) → B:
    tant que c(n) est Faux:
        n ← h(n)
    rendre g(n)

Ce qui permet une implémentation en machine efficace (c'est ce que font les compilateurs lorsque'ils repèrent une telle forme).

Illustrons ceci en utilisant directement l'algorithme d'Euclide pour le calcul du $\operatorname{pgcd}$. On peut en effet écrire cet algorithme sous la forme d'une équation récurrente :

$$ \begin{equation} \operatorname{pgcd}(a, b) = \begin{cases} \max(a, b) & \text{si $\min(a, b) = 0$}\\ \operatorname{pgcd}(\max(a, b) - \min(a, b), \min(a, b)) & \text{sinon}. \end{cases} \end{equation} $$

On a montré en exercice que cette équation est correcte et qu'il se termine en un nombre fini d'étape, c'est donc bien un algorithme qui s'écrit:

algorithme pgcd(a: int, b: int) → int:  # a, b ≥ 0
    si min(a, b) == 0:
        rendre max(a, b)
    sinon:
        rendre pgcd(max(a, b) - min(a, b), min(a, b))

code python

 
def pgcd(a, b):
    if min(a, b) == 0:
        return max(a, b)
    else:
        return pgcd(max(a, b) - min(a, b), min(a, b))

Il est écrit sous forme terminale et est donc équivalent à l'algorithme itératif suivant :

algorithme pgcd(a: int, b: int) → int:  # a, b ≥ 0
    tant que min(a, b) > 0:
        a, b ← max(a, b) - min(a, b), min(a, b)
    rendre max(a, b)

Tous les algorithmes récursifs ne sont pas sous la forme terminale. Par exemple l'algorithme binaire de Stein n'es pas sous la forme récursive terminale en ligne 7.

Récursion croisée

Une dernière utilisation de la récursion qui peut être utile est la récursion croisée qui définie une fonction par rapport à une autre et réciproquement :

Écrire les deux fonctions récursives suivantes sans utiliser de division entière :

algorithme pair(n: entier) → booléen
algorithme impair(n: entier) → booléen

Vous pourrez utiliser le fait que pair(0) est Vrai alors que impair(0) est Faux.

corrigé

 
algorithme pair(n: entier) → booléen
    si n == 0:
        rendre Vrai
    rendre NON impair(n - 1)

algorithme impair(n: entier) → booléen
    si n == 0:
        rendre Faux
    rendre NON pair(n - 1)

La finitude est claire puisque :

  1. il n'y a qu'un appel récursif
  2. chaque appel se rapproche strictement de la condition d'arrêt

La correction est évidente par définition de la parité.
